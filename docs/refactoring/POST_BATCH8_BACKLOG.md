### 9.1 Vision для Custom (OpenAI-Compatible API) — ремонт (решение Дмитрия 2026-10-11, Batch #8.15 §9)

* Источник: BATCH8_15_HIDDEN_BUGS_REPORT.md §9 + проверка агента 2026-10-11
  (T8.15.3/T8.15.4 не тестировались: функция не работает с локальными
  провайдерами/моделями).
* Причина: vision привязан к точному whitelist `LLMClient.VISION_MODELS`
  (llm_clients.py:374; только openai/claude/gemini и конкретные имена моделей,
  двойной гейт: монолит + клиент @858). Ключа `custom_openai` нет → всегда
  «doesn't support vision». Механизм формирования и отправки изображений для
  custom_openai готов (ветка `_call_openai_with_usage`, base64-пары — доказано
  пробой 8.15 §4.4/§4.8).
* Варианты ремонта (рекомендации агента, выбрать в промпте батча): (a) паттерн/
  подстрока в проверке для custom_openai (vl/vision/llava…); (b) ручная галка
  «модель поддерживает vision» в настройках провайдера; (c) расширение whitelist
  именами конкретных моделей. Только custom_openai.
* **Local LLM (Ollama) — НЕ ремонтировать**: провайдер использоваться не будет
  (решение Дмитрия). У ollama, кроме whitelist, `_call_ollama` не принимает
  images вовсе (llm_clients.py:869/1577) — отмечено, чтобы не считалось дефектом.
* **Облачные провайдеры остаются как есть** (не в приоритете; Дмитрий протестирует
  по возможности).
* Проектный приоритет (записан в PROJECT_STATUS): облачные провайдеры НЕ в
  приоритете; приоритет — локальные провайдеры OpenAI-Compatible API и модели.
* **Решение Дмитрия 2026-10-11 (R9, ответ 4): вариант (b) — чекбокс «модель
  поддерживает vision» в профиле Custom.** Реализация — под-батч 9.5 в серии
  консолидации провайдеров (план и зоны: `R9_PROVIDERS_RECON_REPORT.md` §Ч3);
  старт только по команде Дмитрия и его промпту.
