BATCH I2 — экспорт в InDesign Tagged Text из программы: пункт меню + окно «роль → имя стиля».
Первый батч I-серии, правящий продукт. Основа: modules/tagged_text/ (I1/I1.1, принят). Пуш делает Дмитрий.

ЦЕЛЬ: Project → Export → «InDesign Tagged Text (TXT)…» (рядом с «Simple Text File — Translated (TXT)…»):
выбор файла → окно соответствий → запись файла → окно отчёта.

ШАГ 0 — read-only проверка достижимости и фактов (в отчёт, до правок):
(а) как export_simple_txt собирает переведённый текст (groupby paragraph_id + join_segments), что он делает
    с пустым переводом; (б) где хранится путь исходного md проекта (для папки images и имени файла по
    умолчанию); (в) как устроены данные в data root и seam SUPERVERTALER_DATA_ROOT, прецедент
    segmentation_rules (SETTINGS_KEY, виджет с load/save-колбэками) — взять как образец; (г) как
    называются и переводятся строки меню соседних пунктов (translations/); (д) есть ли готовая функция
    «текст проекта → md-строки», которую можно вызвать без копирования кода.
ШАГ 1 — реализация:
1. Источник текста — ТОТ ЖЕ, что у export_simple_txt (правило пустого перевода — как там; зафиксировать
   в отчёте). Если нужен общий хелпер — вынести ТОЛЬКО его, поведение и regress-хэш
   export_simple_txt (5a12501f934a589c) не менять. Текст → modules.tagged_text (md_to_blocks → writer).
2. Окно «Экспорт в InDesign Tagged Text»: таблица «роль → имя стиля InDesign» для ролей h1, h2, h3, p, li,
   li_n, img, table_row и символьных Bold/Italic/BoldItalic, колонка с пояснением роли (h1 — заголовок
   главы, h2 — раздел, h3 — подзаголовок, p — абзац, li — маркированный пункт, li_n — нумерованный,
   img — метка изображения, table_row — строка таблицы, временно); имя стиля — любая непустая строка;
   подсказка: для группы стилей писать «Группа:Стиль» (писатель экранирует «:»); кнопка «Сбросить»;
   поле «серия» (имя набора соответствий) с выбором из имеющихся; кнопки загрузки/сохранения; поле
   «папка images» (по умолчанию — из шага 0б, иначе пусто) — только для проверки «найдено/не найдено».
   Сохранение: <data_root>\mapping\<серия>.tagmap.json (формат stylemap.py), последняя серия и папка —
   в settings.json по образцу segmentation_rules; запись через seam, ничего вне data root, реестр не
   трогать.
3. Запись: UTF-16LE+BOM (единственная кодировка), имя по умолчанию <проект>.tagged.txt, диалог сохранения
   в последнюю папку. Окно отчёта: ExportReport.to_text() (роли, сущности, снятые выделения,
   предупреждения: таблицы не собраны, картинки не найдены, несбалансированные ** и т. д.) + кнопка
   «Копировать». В предупреждениях по возможности указывать номер строки md (если это малая правка
   в пакете tagged_text — разрешена, с тестами).
4. Пункт меню доступен при открытом проекте; строки UI — по правилам соседей (шаг 0г).
5. Копирование картинок в этом батче НЕ делать (только отчёт найдено/нет).
ТЕСТЫ: headless-тесты окна/хендлера с подменой модалок (offscreen, по образцу прежних батчей), прогон
на двух реальных md (docling и PyMuPDF4LLM): проект из md → экспорт → сравнение с CLI-выходом
пакета tagged_text для того же текста (побайтово при пустом переводе = исходнику или по правилу шага 0а).
