Г) ОСОБЫЙ СЛУЧАЙ — _get_line_edit_text(self, attr_name: str) -> str:
   Тело: `widget = getattr(self, attr_name, None)`; если не жив —
   `setattr(self, attr_name, None)` и вернуть ""; иначе `widget.text()`.
   Это НЕ чистая функция по своей природе — она резолвит атрибут ПО ИМЕНИ на
   self И умеет чинить self (обнулять атрибут мёртвого виджета). Такое
   поведение специфично для MainWindow, переносить его в "чистый" модуль
   как есть — нарушить архитектурное решение владельца (без self в
   helpers.py).
   РЕКОМЕНДАЦИЯ (не обязательное решение, оценить самостоятельно): оставить
   getattr/setattr-логику В ДЕЛЕГАТЕ (она и так self-специфична), а в
   helpers.py вынести только переиспользуемую часть — проверку живости и
   извлечение текста уже из ГОТОВОГО виджета (может быть, вообще не нужна
   отдельная pure-функция, раз вся логика после `_widget_is_alive` — это
   `widget.text()`, тривиально). Пример делегата:
   ```
   def _get_line_edit_text(self, attr_name: str) -> str:
       widget = getattr(self, attr_name, None)
       if not self._widget_is_alive(widget):  # тоже делегат к helpers
           setattr(self, attr_name, None)
           return ""
       return widget.text()
   ```
   Главное требование — ВНЕШНЕЕ поведение (что видят 6 вызывающих мест на
   строках ~52287/52288/56227/56228/57365/57366) не меняется НИ НА БИТ.
   Если агент найдёт более удачное разбиение (например, отдельная pure-
   функция get_line_edit_text(widget) -> str, вызываемая из делегата после
   getattr) — допустимо, обязательное условие — сохранить и getattr, и
   setattr-починку в делегате (self-специфичны, не в модуле).

Д) КРИТИЧЕСКИЙ КРОСС-БАТЧЕВЫЙ РИСК — UndoManager (Batch #5):
   modules/undo_manager.py получает в конструкторе колбэки на
   self._find_row_for_segment И self._select_grid_row_by_id (bound-методы
   SupervertalerQt, захваченные при создании self._undo_manager в __init__).
   Оба метода — в составе ЭТОГО батча (helpers.py). После переноса это по
   -прежнему должны быть bound-методы SupervertalerQt (делегаты), иначе

   существовать под тем же именем (тогда всё само работает, колбэк в
   UndoManager как был бound-методом, так и остался — просто теперь это
   тонкая обёртка), либо (если по ошибке эти два метода станут ТОЛЬКО
   функциями в helpers.py без делегата в монолите) — конструктор
