Q.1 — поля max_tokens / timeout_min / extra_body в MT-профилях (вариант 1, без миграции, без vision)
 - В редактор MT-профилей (Supervertaler.py около :20110-20246, populate/sync/save) добавить три поля по образцу LLM-редактора (:19482-19523):
   те же подписи, подсказки, значения по умолчанию (пусто = дефолт), запятая как десятичный разделитель в timeout (как G3.2g).
 - Валидация при Save теми же функциями и теми же текстами (parse_profile_request_fields), с названием профиля в окне; Save блокируется.
 - Хранение: в словаре профиля custom_mt_profiles, значения строкой с точкой; пустые поля — ключ не пишется (как у LLM-профилей).
 - call_custom_mt: передавать **self._custom_profile_request_kwargs(profile) (профиль конкретно того MT, а не только активного).
   Проверить, что QuickTrans MT, пакетный MT и любой другой живой вызов call_custom_mt используют именно профиль своей строки.
 - Ошибки MT: типизированные LLMTruncatedError/LLMEmptyResponseError/LLMTimeoutError не должны превращаться в вводящую в заблуждение строку
   «[MT proxy not running. Start it.]». Показывать краткий текст реальной ошибки в той же «[…]»-форме (одна строка, без трейсбека).
   Легаси-текст оставить только для реальной недоступности эндпоинта.
 - Профили без новых полей: тело запроса байт-в-байт как до правки.
Q.1, формат ошибок MT: показывать так же, как уже делает LLM-ряд панели: «[Error: <краткий текст ошибки>]» одной строкой
(красный текст ошибки сохраняется существующим правилом: строка начинается с «[»). Не придумывать новый формат.

Q.2 — link-only в QuickTrans (панель и popup)
 - Гейт на самом нижнем общем месте, чтобы покрыть все входы: MTFetchWorker.fetch_single (или эквивалент), _call_llm_translation, и верхний уровень
   QuickTransPanel._do_fetch / popup start_fetching, если нижнего общего места нет. is_image_links_only использовать как есть.
 - Link-only: сетевой запрос НЕ уходит; в ряд кладётся исходник дословно с пометкой «⤳ link-only — не отправлено»; вставка в target как обычный
   результат (draft при вставке, как в M1), TM-запись не выполняется. Кнопка Fetch в LLM-блоке на link-only работает так же (без сети).
 - Смешанные сегменты (ссылка + текст) идут как раньше.

Q.6 — кооперативная отмена при закрытии QuickTrans
 - closeEvent панели (quicktrans.py около :1628-1635) и popup (около :1293-1306): флаг «закрыто»; результат после закрытия отбрасывается и не пишется в UI;
   нет висячих QThread и ошибок в консоли при закрытии во время запроса.
 - Реальный abort сетевого вызова не делаем. В отчёте прямо указать, что запрос доживает до ответа/таймаута на стороне сервера.
