## 1. Что сделано

### Задача А — модуль `modules/md_table_cells.py` (новый, 231 строка, LF, без BOM)

Только pure-функции и один dataclass; зависимостей от Qt и от Supervertaler.py нет
(stdlib: `re`, `dataclasses`, `typing`). Публичный API — по промпту:

* `split_table_row(line) -> list[str] | None` — табличная строка только если после
  `strip()` начинается с «|» и заканчивается **неэкранированным** «|» (длина ≥ 2);
  разбор по неэкранированным «|» с учётом чётности обратных слэшей (нечётное число
  перед «|» = экранирован, «\|» → «|» в тексте ячейки); края ячейки обрезаются;
  остальное содержимое не меняется; не таблица → None.
* `is_table_separator(line) -> bool` — табличная строка, все ячейки которой после
  trim подходят под `^:?-+:?$`. «---» без «|» — не разделитель.
* `find_table_blocks(lines) -> list[TableBlock]` — блок = максимальная серия подряд
  идущих табличных строк; `TableBlock(start, end, rows, header, separator_index,
  n_cols_header, warnings)`. `rows` — все строки блока **кроме разделителя**, включая
  строку заголовка (`rows[0]` при `header=True`); разделитель не на 2-й позиции блока
  отбрасывается (не попадает ни в `rows`, ни в `separator_index`) и даёт предупреждение,
  блок при этом продолжается; блок из одной строки без разделителя — тоже блок
  (`header=False`). Порядок/число ячеек сохраняются как есть (разные числа ячеек не
  выравниваются и не дополняются).
* `build_table_row(cells) -> str` — непустая ячейка « текст », пустая « »;
  `'|' + '|'.join(...) + '|'`; экранирование и CR/LF→пробел внутри. Примеры промпта
  воспроизведены тестами: `["a","b"]` → `| a | b |`; `[""]` → `| |`; `["a","","b"]` →
  `| a | | b |`.
* `build_table_separator(n_cols) -> str` — `|---|---|…` (n_cols ≥ 1; n_cols < 1 →
  ValueError). **Выравнивание («:---:», «---:») не сохраняется** — при сборке всегда
  канонический «|---|»; зафиксировано в докстринге модуля (решение 1).
* `escape_cell(text)` / `unescape_cell(text)` — публичные функции (CR/LF→пробел +
  «|»→«\|»; обратное — с учётом чётности слэшей).

«<br>» и «**» в ячейках не обрабатываются — остаются в тексте как есть (решение 5,
тест `esc.br_kept`/`build.br_kept`). Докстринги с «\|» — raw-строки (SyntaxWarning
проверены чистым импортом с `-W error::SyntaxWarning`).

   (models.py:292–298); загрузка нигде не обходит from_dict, править другие пути
   не потребовалось.
2. **`\\|` и строка на «\|».** `\\|` (двойной слэш + «|»): чётное число слэшей → «|»
   НЕэкранирован → это **разделитель столбцов**, сами слэши остаются в тексте ячейки
   как есть (тест `split.backslash_before_pipe`: `| a \\| b |` → `['a \\', 'b']`).
   Строка, оканчивающаяся на «\|»: последний «|» экранирован → условие «заканчивается
   НЕэкранированным «|»» нарушено → **не таблица** → `split_table_row` возвращает
   None (тест `split.ends_on_escaped_pipe`).
3. **Образцы md_out против find_table_blocks.** Расхождений нет; «разорванных» строк
   с разным числом ячеек в текущих образцах **не оказалось** (скан всех pipe-строк
   обоих файлов: числа ячеек внутри каждой таблицы равномерны). «Было» (разведка
   TBL1.0) / «стало» (модуль): PyMuPDF4LLM Input.md — 2 таблицы (строки 7–11: шапка +
   разделитель + 3 строки, 2 столбца; строки 19–26: шапка + разделитель + 6 строк,

   же 2 таблицы (строки 7–11 и 17–24) → те же 2 блока, паддинги пробелами обрезаются,
   длинный разделитель распознаётся как разделитель. Кейс «разорванной» строки покрыт
   синтетическим тестом `blocks.ragged` (сохраняется как есть) — в отчёте TBL1.0
   обещанного образца такой строки нет.
4. **Места, где table_info/is_table_cell читается как список.** Не найдено. Полный
   список потребителей (после исключения `PRAGMA table_info` — это SQLite, другое):
