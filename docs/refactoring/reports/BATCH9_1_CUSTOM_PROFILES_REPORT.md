## §7 Непокрытые проверки и находки

1. **Полный запрос к фейк-endpoint не прогонялся**: в dev-runtime нет пакета `openai`
   (R9 §2.8); по условию промпта НЕ ставился. Проверено конструирование LLMClient и
   передача base_url (c3). Полный e2e-запрос — на тестовой сборке (T9.1.5) или после
   установки `openai` перед 9.2.
2. **Методологическая находка**: у простаивающего offscreen-экземпляра (после завершения
   старта) stdout нестабилен — процесс может завершиться с кодом 0 до выполнения финальных
   печатей (проба MT). Вердикты надёжно писать в файл (`mt_verdict.json`); интерактивные
   пробы (клики по виджетам) этим не страдают. Один запуск завис на регистрации
   глобального хоткея (конфликт с остаточным хуком) — лечится taskkill + повтор.
3. `_save_llm_settings_from_ui` (мёртвый, 23730–23810 в координатах R9) по-прежнему содержит
   старый код сохранения — при будущем «оживлении» может вернуть баг; кандидат 8.18 (не трогали).
4. QuickTrans `call_custom_mt._clean` (48420+) чистит управляющие символы, но не добавляет
   схему — теперь схема приходит нормализованной из ридера; ручной ввод в MT-профиль
   нормализуется ТОЛЬКО на чтении (решение по промпту — на записи не трогали).
5. Проверка «перезапуск вкладки после Save» в пробах a/rm выполняется повторным вызовом
   `_create_ai_settings_tab()` в том же процессе, а не рестартом приложения; рестарт покрыт
   ручным T9.1.2/T9.1.4.
6. G5-зона не тронута: figure-regex, PreTranslationWorker, Image Extractor, `figure_context_manager.py`.
   G3.x не тронута: `LLMClient`, `create_llm_client` (нормализация пришла из ридера, сам клиент
   не менялся).
