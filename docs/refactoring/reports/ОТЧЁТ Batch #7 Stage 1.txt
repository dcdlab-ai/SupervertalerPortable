3) Блокер — не цикл, а неразрешимые глобальные имена монолита:
   • load_language_settings (45228–45249) ссылается на TagHighlighter (класс монолита,

     ReadOnlyGridTextEditor, SupervertalerQt (классы монолита);

     self.current_project, self.project_file_path, self.MAX_RECENT_PROJECTS, QMessageBox
     и UI-методы update_recent_menu/update_recent_projects_display.
4) Обратного направления (сервис → монолит) нет ни в одном варианте: делегаты живут в
   монолите и импортируют сервис (монолит → modules.settings_service). Цикл не
   появится при условии, что modules/settings_service.py НЕ импортирует
   termbase_entry_editor/voice_tab/clipboard_manager_widget/quicktrans — они общаются
   с сервисом только через parent_app-дукт-тайпинг (в импорте не нуждаются).

1.7 РЕКОМЕНДАЦИЯ ПО АРХИТЕКТУРЕ (решение — за владельцем)
════════════════════════════════════════════════════════════════════════════
РЕКОМЕНДАЦИЯ: вариант (б) в модифицированной форме — новый
modules/settings_service.py с КЛАССОМ, который конструируется явным путём
(settings_dir: Path, опционально log: Callable[[str], None]) и НЕ резолвит user_data
через ConfigManager.get_user_data_path(). ConfigManager остаётся владельцем «где лежит
user_data» для внешнего мира; его дубликаты load_preferences/save_preferences выводятся
из эксплуатации отдельным решением (не в Stage 2).

Обоснование (по фактам 1.5, а не «как в Step 5/6»):
1) Всему составу нужны ровно два внешних входа: каталог настроек и лог-колбэк
   (26 методов — только путь; 13 — путь + лог; 3 — ещё путь recent_projects.json;
   4 — UI/БД и потому не переносятся «как есть»). Любая «обёртка с состоянием» избыточна.
2) Путь нельзя брать из ConfigManager: разные файлы-указатели (см. 1.5) → риск молча
   читать/писать чужой settings.json. Явный settings_dir = тот же каталог, что сейчас
   (self.user_data_path / "workbench" / "settings"), снимает риск без унификации.
3) Вариант (а) «расширить ConfigManager» отклонён: (i) тянет bootstrap первого запуска
   и свой указатель; (ii) внутри уже лежат мёртвые дубликаты load_preferences/
   save_preferences для ЭТОГО ЖЕ файла — их судьбу пришлось бы решать в том же
   механическом батче; (iii) класс стал бы смешанной ответственностью
   (bootstrap + формат settings + дефолты секций).
4) Вариант (в) «чистые функции с явными параметрами» (стиль Step 6) рабочий, но
   проигрывает: есть общий инвариант (4 секции api_keys/general/ui/features + дефолты
   доменных аксессоров), который в виде функций разъедется по модулю без единой точки
   контракта; класс = одна точка владения форматом и при этом остаётся stateless между
   вызовами (никакого кэша — см. 1.9).
5) Делегаты обязательны при любом выборе: 11 внешних дукт-тайпед-консументов
   обращаются к 6 именам, включая приватные — имена и сигнатуры в монолите
   сохраняются 1:1.
