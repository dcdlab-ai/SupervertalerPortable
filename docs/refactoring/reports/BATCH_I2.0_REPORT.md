# ОТЧЁТ BATCH I2.0 — «Start a new segment at every line break»: влияние на импорт md и экспорт Tagged Text

Дата: 2026-11-07. Исполнитель: агент (ZCode). Координатор: Дмитрий.
Только чтение + прогоны на копии; **продукт не правился** (git diff по коду пуст,
проверено перед коммитом). Коммит — только docs.

## s0. Итог

1. **На импорт md из ФАЙЛА настройка не влияет вообще** — ни при выключенном,
   ни при включённом «Split lines into sentences». Файл-импорт зовёт сегментер
   **построчно** (в одной строке нет `\n`), а ветка правила включается только
   когда в ОДИН вызов приходит многострочный текст. Прогон подтвердил:
   docling Input.md, чекбокс ON + правило OFF и чекбокс ON + правило ON —
   идентичные результаты (63 сегмента в 44 группах, одинаковые разрезы,
   одинаковые байты экспорта `f51c1f39…` = хэш T-I1a2).
2. **На экспорт Tagged Text настройка не влияет.** Экспорт собирает строки
   из сегментов (`join_segments`/`join_before`) и во всех состояниях даёт
   байт-в-байт тот же файл, что CLI `python -m modules.tagged_text` на
   исходном md; склейка восстанавливает исходные строки (rejoined == source:
   True во всех кейсах).
3. **Наблюдение Дмитрия воспроизводится только на пути ВСТАВКИ текста в
   New Project** (Supervertaler.py:25973–25974: `segment_text(source_text)` —
   весь текст за один вызов, `SimpleSegmenter`, markdown=False → картинки НЕ
   защищаются плейсхолдерами). Юнит-прогон на том же docling md:
   правило OFF (дефолт) → **22 юнита, 0 изолированных картинок** — строки
   сливаются в поток предложений (`## ANTIDOTE TO THE ENGLISH ## DEPLOYMENT
   Consult the map…` — один сегмент); правило ON → **47 юнитов (по строке),
   2 картинки изолированы**, таблицы построчно. Это в точности наблюдение:
   «ON — таблицы по строкам и картинки отдельными сегментами; OFF — таблицы
   режутся, картинки НЕ отдельные».
4. **table_row (п.4 промпта): в обоих состояниях все 11 строк данных таблиц
   получают `<ParaStyle:table_row>`**; из 13 строк файла, начинающихся с `|`,
   2 — разделители (строки 8 и 18, по одному на каждую из двух таблиц), они
   отбрасываются by design (I1: `table_separators_dropped=2`). Разрезанные
   при сегментации строки 19–20 склеиваются на экспорте обратно в исходные
   строки — стилевая разметка не меняется.
5. **Рекомендация (s4):** для md-проектов из файлов состояние настройки
   нейтрально — менять дефолт (OFF) не нужно; для вставки md в New Project
   правило ON сохраняет построчную структуру (единственный путь, где ON/OFF
   видно). Хинт в окне экспорта не нужен — экспорт не зависит от настройки;
   если делать хинт, то в окне импорта/настройках сегментации (см. s4).

## s1. Где и как читается настройка (п.1 промпта)

**Хранение.** `modules/segmentation_rules.py:63` —
`SegmentationRules.split_at_line_breaks: bool = False` (**дефолт на чистой
установке — OFF**; `from_dict` :80 — тот же дефолт при отсутствии ключа).
SETTINGS_KEY = `"segmentation_rules"`; файл — единый
`<data_root>\workbench\settings\settings.json`, секция `general`
(SettingsService, `settings_service.py:15`: `user_data_path / "workbench" /
"settings"`).

**UI.** `modules/segmentation_rules_widget.py:63–68` — чекбокс
«Start a new segment at every line break»; запись через `rules()` :188
(`split_at_line_breaks=self.line_breaks_cb.isChecked()`), установка из модели
:168; сохранение мгновенное (load/save-колбэки монолита
`_load_segmentation_rules`/`_save_segmentation_rules`, Supervertaler.py:13978/13986).

**Действие.** `modules/simple_segmenter.py:63–76`: если правило включено —
текст режется по `\r\n|\r|\n`, каждая строка дополнительно прогоняется через
`_split_line` (правила предложений); если выключено — все переводы строк
заменяются пробелами и текст сегментируется сплошным потоком
(`:72` «Line breaks inside the text are treated as spaces»).

**Связь с опцией импорта «Split lines into sentences».** Опция чекбокса
диалога импорта (дефолт = `last_import_sentence_segment`, на чистой
установке False; Supervertaler.py:29669–29671) решает, звать ли сегментер
вообще. При ON: `_make_sentence_segmenter(markdown=is_markdown)`
(:13992–13996) → `MarkdownSegmenter(rules)` для md — **плейсхолдер-защита
картинок/ссылок/кода + те же правила**; при OFF сегментер не зовётся (1
сегмент = 1 строка).

**Места вызова сегментера в монолите (полный список):**
- `import_simple_txt` :29750 (и fallback :29872) — **построчно**, правило
  не может действовать;
- `_import_multifile_project` :30884 — **построчно**, то же;
- `new_project` :25973–25974 — **весь вставленный текст одним вызовом**
  (`segment_text`), `SimpleSegmenter` (markdown=False) — **единственное
  место в монолите, где правило действует**;
- тестовый бокс виджета правил (segmentation_rules_widget.py:375) — тоже
  одним вызовом.
В modules/* других вызовов нет.

|---|---|---|---|

## s3. table_row (п.4 промпта)

13 строк docling md, начинающихся с `|`: 11 строк данных + **2 разделителя**
(строки 8 и 18 — каждый из двух pipe-файлов начинается своим `|---|`);
разделители отбрасываются парсером (`table_separators_dropped=2`, I1).
Все 11 строк данных → `<ParaStyle:table_row>` (11 вхождений в выходе,
в кейсах A, B2 и C2 одинаково). Строки 19–20, разрезанные при чекбоксе ON на
3 сегмента, склеиваются на экспорте в исходные строки до `parse_markdown` —
разметка не отличается. В pymupdf-варианте (Bp) table_row тоже 11/11.

## s4. Рекомендация (п.5 промпта)

- **Для md-проектов, импортируемых из файлов, состояние настройки
  нейтрально**: она не влияет ни на сегментацию (построчный вызов), ни на
  экспорт. Менять дефолт OFF не нужно; специально включать для md — смысла
  нет.
- **Для вставки md в New Project правило ON сохраняет структуру** (построчно;
  картинки изолированы). OFF «схлопывает» строки в поток предложений — это
  и есть наблюдённый эффект. Если писать хинт, то не в окне экспорта
  (экспорт от настройки не зависит и одинаково восстанавливает строки), а
  в диалоге New Project / окне Segmentation Rules — например: «для вставки
  Markdown включите „Start a new segment at every line break“, чтобы строки
  и картинки не слились». Решение — за координатором.
- Наблюдение для координатора (вне скоупа I2.0, продуктом не правилось):
  сегменты из paste-пути создаются без `paragraph_id` (дефолт `0`,
  modules/models.py:130), поэтому `_collect_translated_lines` (как и
  export_simple_txt) соберёт весь вставленный проект в ОДНУ строку — экспорт
  Tagged Text (и Simple TXT) по вставленному тексту не восстановит построчную
  структуру независимо от настройки. Кандидат в бэклог I-серии.
