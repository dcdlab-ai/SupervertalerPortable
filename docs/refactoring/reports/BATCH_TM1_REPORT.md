## 1. Разведка: старый код и воспроизведение (коммит 1, без правок продукта)

### 1.1 Как старый код брал выделение и удалял

`modules/tm_manager_qt.py:825–852` (снапшот `90d60c42…`, 1255 строк):

```python
selected_rows = self.browser_table.selectedItems()   # ТОЛЬКО проверка «не пусто»
...
row = self.browser_table.currentRow()                # ОДНА строка — якорь выделения
entry_id = int(self.browser_table.item(row, 0).text())
...
self.db_manager.cursor.execute("DELETE FROM translation_units WHERE id = ?", (entry_id,))
self.db_manager.connection.commit()
self.log(f"Deleted TM entry {entry_id}")
self.refresh_browser()
QMessageBox.information(self, "Success", "Entry deleted successfully")
```

* `selectedItems()` использовался только как проверка «что-то выделено»; дальше брался
  **`currentRow()`** — одна строка, якорь выделения. При Shift-выделении якорь = последняя
  кликнутая строка → удалялась именно она.
* После следующего клика выделение схлопывалось, якорь становился «предпоследней» строкой —
  отсюда наблюдение Дмитрия «удаляет последнюю, потом предпоследнюю и т.д.».
* Подтверждение было: `QMessageBox.question` «Delete this TM entry? … This cannot be undone.»
  — на ОДНУ запись; после удаления — модалка «Success» и один `refresh_browser()`.
* Отдельной инвалидации кэшей старый код не делал (FTS5/trigram-индексы SQLite
  поддерживаются триггерами автоматически); «кэш» окна — это перечитывание `refresh_browser()`.

## 2. Исправление (коммит 2, `modules/tm_manager_qt.py:825–887`)

`TMManagerDialog.delete_selected_entry` переписан; остальное окно (фильтры, сортировка,
правка, импорт/экспорт) не тронуто. Разница: 1255 → 1295 строк (+60/−20).

а) **Все выделенные записи**: уникальные строки из `browser_table.selectedIndexes()`
(Shift-диапазон, Ctrl-выборочное, Ctrl+A; выделение по ячейкам схлопывается до уникальных
строк), id берутся из колонки ID (`item(row, 0)`), не из номеров строк. Номер строки —
не стабильный ключ БД: при сортировке/фильтре он не соответствует id.

б) **Ноль выделенных** — прежнее сообщение окна «Please select an entry to delete»
(warning), ничего не удаляется.

в) **Подтверждение** — один диалог на всю пачку:
`Delete N selected entries from TM <id>? This cannot be undone.`; если пачка из нескольких
TM — `from K TMs (id1, id2, …)`. Отмена (`No`) → ничего не удалено. Стиль — плоские
английские литералы, как остальные 2 `QMessageBox.question` в этом модуле (в
`modules/tm_manager_qt.py` `self.tr` не используется ни разу — см. §9, прим. 2).

г) **Одна транзакция**: `connection.commit()` перед пачкой (сброс чужого неявного
транзакционного хвоста, чтобы rollback накрывал ровно эту пачку), затем
`DELETE FROM translation_units WHERE id IN (…)` пачками ≤500 id, затем один `commit()`.
Любое исключение → `connection.rollback()` (в try/except pass) + `QMessageBox.critical`,
частичного удаления нет.

д) **Один refresh**: `refresh_browser()` один раз после успешного коммита (перечитывает
таблицу, статусную строку «Showing N entries»; FTS5/trigram — триггерные, отдельной
инвалидации нет ни в старом, ни в новом коде — паритет со старым кодом на одну запись).
Позиция скролла не сохраняется принудительно — поведение как у старого кода (один
`setRowCount`+заполнение).

е) **Одна строка лога**: `TM Browser: deleted N entries from TM <id>` (для нескольких TM —
`from K TMs (…)`). Старые строки «Deleted TM entry N» / модалка «Success» убраны.

## 4. Ответы на вопросы отчёта

1. **Старый код**: `selectedItems()` — только проверка непустоты; удаление брало
   `browser_table.currentRow()` — одну строку-якорь (последнюю кликнутую при Shift) —
   и выполняло `DELETE … WHERE id = ?` по одному id. Поэтому за клик удалялась одна запись,
   а следующий клик брал следующую за ней.
2. **Изменено и где**: только `TMManagerDialog.delete_selected_entry`
   (`modules/tm_manager_qt.py:825–887`). Одна транзакция: pre-flush commit → пачки
   `DELETE … WHERE id IN (…)` по ≤500 → один `commit`; исключение → `rollback` всего
   набора. Одно обновление кэша: один `refresh_browser()` в конце (у SQLite-индексов
   триггерная поддержка; старый код отдельной инвалидации не имел).
3. **Другие кнопки с тем же шаблоном** — §1.3 (7 позиций, только список, не правились).
4. **Затронутые места** — §7.

## 7. Ручные тесты для Дмитрия (простым языком)

**Подготовка (для всех тестов):** скопировать `modules\tm_manager_qt.py` из репозитория

Нужна TM с записями: если ещё нет — переведите и подтвердите (Ctrl+Enter) несколько
сегментов в любом проекте, чтобы в TM появилось 8–10 записей.

**T-TM1a — удаление диапазона за один клик.** Откройте вкладку **TMs** (внизу окна) →
подвкладка **📖 Browse All**. Выделите 3 подряд записи мышью: клик по первой, затем

(«Delete 3 selected entries from TM …? This cannot be undone.»). Нажмите **Yes**.
Ожидание: все три строки исчезают за ОДИН клик; в журнале (Log window) одна строка
«TM Browser: deleted 3 entries from TM …». Провал: удалилась одна строка (осталось ещё две
выделенные), или подтверждение про одну запись.

**T-TM1b — удаление выборочных записей.** В том же окне выделите 2 записи через Ctrl+клик
(не соседние). Нажмите **🗑️ Delete Selected** → **Yes**. Ожидание: исчезли именно эти две
записи, остальные на местах. Провал: исчезли соседние строки с теми же номерами позиций.

**T-TM1c — пустое выделение и отмена.** Снимите выделение (клик по пустому месту списка
не всегда снимает — перезапустите окно или кликните по уже удалённой области: проще всего
сразу после открытия окна ничего не выделять) и нажмите **🗑️ Delete Selected**. Ожидание:
появится сообщение «Please select an entry to delete», ничего не удаляется, окно живо.
Затем выделите 1–2 записи, нажмите удаление и в подтверждении **No**. Ожидание: ничего
не удалилось.

**T-TM1d — фильтр или сортировка.** В поле **Filter** введите кусочек текста, который есть
только у нескольких записей (или кликните по заголовку колонки ID, чтобы отсортировать).
Нажмите 🔄 Refresh, выделите 2 записи, удалите. Ожидание: удалены именно выделенные
(проверьте по колонке ID), а не записи, которые стояли на этих местах до сортировки.

## 8. Примечания к прогонам (для координатора)

1. **Концы строк модуля**: `modules/tm_manager_qt.py` в LF и до, и после правки
   (0 CRLF). В commit-сообщении `c1a074a2` фраза «CRLF preserved» означает «концы строк
   не изменялись» — правило CRLF относится к монолиту `Supervertaler.py`, который в этом
   батче не правился.
2. **Стиль подтверждений**: в промпте — «через self.tr; если принят иной стиль — взять его».
   В `modules/tm_manager_qt.py` `self.tr` не используется ни разу (все строки — плоские
   английские литералы), поэтому взят стиль модуля.
3. **Особенности батареи**: t2-сьют double-write по умолчанию работает в профиле
   `batch-t2\tests\run-001` (остатки T2) — второй прогон даёт фейковые UNIQUE-фейлы
   («Error creating TM: UNIQUE constraint failed: translation_memories.name»); перегнан в
   свежем каталоге через `T2_STAGE` → 31/0. `regress_common` требует предсозданный
   `stage/iso` и `stage/inputs/` (футпринт `batch-p1b_run_full.sh`); без предсоздания —
   FileNotFoundError, после засева → дайджесты совпали. Оба рецепта учтены в
   `battery_dynamic.sh` стейджа (Work_temp, вне git).
4. **Рекон-тест коммита 1** получил `r`-docstring в коммите 3 (SyntaxWarning
   «invalid escape sequence '\D'» от `E:\Dev` в докстринге; поведение теста не менялось —
   финальный прогон OK).
5. Все прогоны — один одновременно, каждая сьют-сессия со своим изолированным
   `SUPERVERTALER_DATA_ROOT`; реальные TM-базы и реестр не тронуты; после батареи
   вычищен 1 осиротевший java-процесс Okapi-сайдкара этой сессии (PID 58636, по
   command-line своей стадии), прочих процессов этой сессии не было.
