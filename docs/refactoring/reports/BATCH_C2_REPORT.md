## §1. Пороги детектора и обоснование

Детектор: `looks_like_context_overflow(response, source_text) -> bool` в
`modules/prompt_markers.py` (рядом с `looks_like_prompt_echo`, тот же модуль —
**нового tracked-модуля нет**, importsmoke не расширялся). Чистая функция, без Qt.
Плюс публичный `count_paragraphs(text)` для строк лога.

Абзац = непустая строка после `strip` (разбиение по `\n`; пробельные строки
между абзацами не считаются).

**Правило (1) — абзацы** (константа `_OVERFLOW_EXCESS_MIN = 3`):
- одноабзацный source (без `\n\n`): перелив при избытке **>= 3** абзацев;
- многоабзацный source (`\n\n` в source): перелив при избытке **>= max(3, число абзацев source)** — порог от числа абзацев source (координатор, задача 1г);
- ответ с МЕНЬШИМ числом абзацев — никогда не перелив (потерю структуры детектор не судит).

Обоснование: ±1 абзац — легитимный допуск (перевод может разбить или склеить
абзац — требование 1б); +2 — запас на граничные случаи многострочных
заголовков; начиная с +3 у одноабзацного сегмента вероятность «ответ — перевод
соседей» доминирует (живой случай: 6 абзацев против 1).

**Правило (2) — длина** (координатор, задача 1в; ТОЛЬКО в сочетании с
превышением строк): source <= 60 знаков (`_OVERFLOW_SHORT_SOURCE_CHARS`) и
ответ >= 10 × длины source (`_OVERFLOW_LENGTH_RATIO`) при абзацев у ответа
строго больше. Само по себе превышение длины — не перелив: короткие заголовки
легитимно дают длинный перевод одной строкой (пара A19: 13 знаков source →
~500 знаков одной строкой — False).

Пустой/пробельный ответ → False (его обрабатывает существующая логика);
пустой/пробельный source → False.

**Таблица пар** — 34 строки в `docs/refactoring/audits/c2_context_overflow_tests.py`

**Анализ ложных срабатываний:**
- Легитимный перевод одноабзацного source в 3+ абзаца — единственный класс
  FP правила (1). В CAT-практике одноабзацный сегмент (заголовок/короткая
  фраза) редко даёт 3+ абзаца; цена FP — один лишний LLM-вызов без контекста
  и/или пропуск перевода (никаких записей/потерь данных — target/TM/undo не
  трогаются).
- Правило (2) может сработать на коротком source (<=60 зн.) с легитимным
  многоабзацным переводом >=10× длины — тот же класс редких FP, та же цена.
- В экспорте Tagged Text (§3-писатель) сигнатурой серии служит совпадение
  source у последовательных строк; теоретический FP — два соседних сегмента с
  одинаковым source и суммарно «переливным» переводом. Экспорт при этом НЕ
  блокируется (только предупреждение).
- Поведение при FP: повтор без контекста обычно возвращает корректный
  перевод; повторное срабатывание на чистом запросе — только пропуск сегмента,
  данные не портятся.

## §2. Интеграция (задача 2)

Только `translate_current_segment` (монолит), рядом с защитой C1, тот же
сценарий: **один повтор БЕЗ блока окружающих сегментов**, при повторном
переливе или эхе — пропуск (target/TM/undo/статус не трогаются, без модалок).
Сообщения C1 не менялись (c1 33/0 сохранён); вырезание контекста — та же
пара веток `replace`/`endswith` (6 строк продублированы вместо рефакторинга
C1-ветки: правка «заодно» исключена).

**Как определяется «контекст был в запросе»:** флаг
`_overflow_request_had_context = bool(surrounding_context)` на момент запроса,
породившего текущий `translation`:
- первый запрос строится с контекстом только если `surrounding_context` непуст
  (блок добавляется в :48670–48680 при `surrounding_segments > 0` и наличии
  соседей);
- эхо-повтор C1 снимает флаг в False (запрос уже шёл без контекста) —
  перелив после эхо-повтора даёт сразу пропуск;
- перелив-повтор тоже снимает флаг — второй повтор невозможен;
- запрос изначально без контекста → сразу пропуск, повтора нет.

Логи (английские, отдельные от C1):
- `Segment #N: response looks like a context overflow (X paragraphs vs Y in source); retrying without context`
- `Segment #N: translation skipped (context overflow persists)`
- без повторного запроса: `Segment #N: translation skipped (context overflow, no context in request)`

## §3. Разведка (задача 4)

**4а. Пакетный перевод («перевести всё»):** нет контекста, перелив невозможен.
Путь: `Translate → Translate all …` → `translate_multiple_segments` (:49484) →
`translate_batch` (:49719) → `PreTranslationWorker` (QThread, :5154). Обе
LLM-ветки воркера (по-сегментная ~:5515 и многосегментная
`_translate_batch_with_llm` ~:5570) строят промт через
`build_final_prompt(mode="single")` БЕЗ блока SURROUNDING (он добавляется
только в `translate_current_segment` :48670–48680) и вызывают
`client.translate(...)` без `detect_prompt_echo` (дефолт False; True передаёт
только Ctrl+T — комментарий C1 «только здесь»). Замечание: эхо-защита C1 в
пакетном пути тоже отсутствует; у многосегментного пакетного вызова другой
класс риска (модель отвечает нумерованным списком не на все сегменты) — он
ловится парсером пакетного ответа, вне рамок этого батча.

**4б. Контекст для TABLE_CELL:** да, кладётся общий соседний контекст — блок
(:48636–48651) берёт `segments[start_idx:end_idx]` ПО ПОРЯДКУ СПИСКА (порядок
чтения: строка за строкой, ячейка за ячейкой), т.е. для ячейки «5 до/5 после»
= соседние ячейки той же строки и соседних строк, в виде `N. source` (плюс
`→ target` для уже переведённых). Ячейка помечается `>>> N. source <<<  [TRANSLATE THIS]`.
Варианты сделать контекст ячейки менее «провоцирующим» (НЕ реализовано):
1. *Контекст только ячейками той же строки таблицы* — фильтр по
   `seg.is_table` + `table_info == (table_index, row_index, _)` (информация
   уже есть на сегментах, монолит :29376–29382); заголовочную строку включить
   всегда. Стоимость ~10 строк в построителе блока. Риск: для широких таблиц
   контекст скудеет (смягчается включением заголовка); оценка: низко-средний.
2. *Пометка ячеек в контексте* — префикс `(table cell)` у соседей + строка
   «соседи — ячейки таблицы, переводить только отмеченное» (см. 4в).
   Стоимость ~2 строки, риск низкий.
3. *Уменьшить окно для ячеек* (например, 2 до/после) — проще всего, риск
   качества средний.
Рекомендация: 1 + 2 вместе.

**4в. Инструкция «translate ONLY the marked segment»:** явной инструкции НЕТ.
Текущие тексты (Preview Prompts):
- системный шаблон (modules/unified_prompt_manager_qt.py, дефолт :4063):
  `**YOUR TASK**: Translate the text below.` + `- Provide ONLY the translated text` /
  `- Do NOT include numbering, labels, or commentary` / `- Do NOT repeat the source text`;
- финальный разделитель (:4159): `**YOUR TRANSLATION (provide ONLY the translated text, no numbering or labels):**`;
- единственное «отмеченное»-указание — эксплейнер блока контекста
  (modules/prompt_markers.py:17): `(The segment marked with >>> <<< is the one to translate)`.

Усилить МОЖНО и дёшево, но не в этом батче: кандидат — добавить строку ВНУТРЬ
блока контекста (тогда она живёт и умирает вместе с блоком, байт-стабильность
через константы prompt_markers):
`The numbered segments are CONTEXT FOR REFERENCE ONLY — do NOT translate them. Translate ONLY the segment marked with >>> <<<, preserving the paragraph structure of that segment (a single-paragraph segment must yield a single paragraph).`
Общий вариант обходит ловушку «Output exactly one paragraph» (неверно для
многоабзацного сегмента) условием по структуре самого сегмента. Риск/стоимость:
меняется байтовый состав Ctrl+T-запроса → изменится e2e-агрегат (982e72a247f0a6ac)
и байт-точные проверки c1 (C2/C3 сверяют промт с прежней сборкой) — нужен
отдельный микробатч с согласованным обновлением эталонов, не «заодно».

## §6. Ручные тесты для Дмитрия

**T-C3 — перелив ловится.**
1. Цель: убедиться, что перелив контекста теперь перехватывается.
2. Подготовка: в `D:\Supervertaler_clean` подменить `SupervertalerPortable\Supervertaler.py` файлом из репозитория; модель index-nailong-9b (LM Studio).
3. Шаги: импортировать docling `Input.md` с включённой галкой «Recognize tables»; выделить короткую ячейку первой колонки таблицы («Bridge Guards», «Refuge in the Church», «Main Allied Line» и т.п.) и нажать Ctrl+T несколько раз (5–10 попыток на разных коротких ячейках).
4. Ожидаемый результат: если перелив случится — в логе строка вида «Segment #N: response looks like a context overflow (…paragraphs vs … in source); retrying without context», затем либо нормальный перевод в target, либо «translation skipped (context overflow persists)» (сегмент остаётся непереведённым, никаких «шести абзацев» в target). Если перелив не случится — просто переводы по одной ячейке.
5. Провал: в target попадает перевод нескольких ячеек сразу без лога перелива.
Поведение модели недетерминировано — запиши, сколько попыток сделано и был ли перелив.

**T-C4 — нет ложных срабатываний.**
1. Цель: обычные сегменты не должны задеваться защитой.
2. Шаги: тем же проектом перевести подряд 10–15 обычных ячеек и абзацев, включая длинную ячейку с переносами строк (`<br>`) и сегмент из нескольких абзацев.
3. Ожидаемый результат: все переводы попадают в target как обычно; в логе НЕТ строк «context overflow».
4. Провал: у нормально переведённого сегмента в логе появился перелив, а target пуст («skipped»).

**T-C5 — Tagged Text: предупреждение о переливе.**
1. Цель: экспорт предупреждает о переливе, уже лежащем в target.
2. Подготовка: в любом проекте вручную вставить в target одной ячейки несколько абзацев (например, скопировать туда 3–6 абзацев текста) при source в одну строку.
3. Шаги: File → экспорт InDesign Tagged Text.
4. Ожидаемый результат: в окне отчёта экспорта появляется предупреждение «возможный перелив контекста (строка N): …» (в том же блоке, что и предупреждение об эхе промта). На обычных проектах новых предупреждений нет.
5. Провал: предупреждение не появилось либо экспорт заблокирован (экспорт блокироваться не должен).
