2.1 Pink/Blue/Orange vs CheckmarkCheckBox — ИДЕНТИЧНЫ С ТОЧНОСТЬЮ ДО ЦВЕТА:
- Статически: paintEvent монолитных версий отличается от базового только
  формой записи (guard-return вместо if-блока, ленивые импорты внутри метода,
  painter.end() без try/finally); геометрия, pen_width (max(2.0, min*0.12)),
  padding (0.15), точки галочки (0.10/0.50, 0.35/0.70, 0.90/0.25), порядок
  drawLine — построчно совпадают. Stylesheet отличается РОВНО 4 hex-значениями
  (checked bg/border + checked:hover bg/border), всё остальное байт-идентично
  (посимвольный diff, включая индентацию).
- Динамически (offscreen, пиксельное сравнение рендеров, 12 сценариев —
  по 4 на каждый цвет): unchecked, checked, checked+resize(240,30),
  disabled+checked — монолитный класс vs базовый CheckmarkCheckBox с
  подставленным stylesheet монолитного класса = pixel-identical во всех 12.
  Sanity: pink checked ≠ blue checked (отличаются только цветом — ожидаемо).
- СПОСОБ ЗАШИВКИ ЦВЕТА: hex-константы внутри stylesheet-строки в __init__
  (не class-атрибут, не аргумент конструктора). Отсюда параметризация:
  приватная база _ColoredCheckmarkCheckBox(CheckmarkCheckBox) + шаблон
  stylesheet с двумя подстановками; Pink/Blue/Orange — тонкие подклассы с
  двумя class-атрибутами (_checked_color/_checked_hover_color). Тело
  paintEvent НЕ дублируется (унаследовано). Существующие
  CheckmarkCheckBox/Purple/Teal/CheckmarkRadioButton не изменялись ни на байт.

2.2 CustomRadioButton vs CheckmarkRadioButton — РАЗНЫЕ ВИДЖЕТЫ (не объединены):
- Монолит: индикатор 18px, border-radius 9px, checked = БЕЛЫЙ фон + зелёное
  кольцо #4CAF50 (заливка не меняется), hover #666, checked:hover кольцо
  #45a049; paintEvent рисит ЗЕЛЁНУЮ точку #4CAF50 радиусом min(w,h)*0.25
  (drawEllipse(QRectF...), кисть QColor("#4CAF50")).
- styled: индикатор 16px, checked = ЗЕЛЁНАЯ ЗАЛИВКА #4CAF50, paintEvent
  рисит БЕЛУЮ точку радиусом width*0.25 (drawEllipse(QPointF...), кисть white).
- Пиксельные рендеры checked различаются (в т.ч. размер 124x22 vs 122x20).
- РЕШЕНИЕ ПО ПРОТОКОЛУ: Этап 2.2 прямо предусматривает этот исход («наиболее
  вероятный по имени сценарий») — CustomRadioButton перенесён ВЕРБАТИМ
  отдельным классом, БЕЗ слияния. Байт-в-байт равенство перенесённого тела
  снапшоту из git HEAD подтверждено (sha256 062ae656… совпадает). Это НЕ
  стоп-условие: расхождение не требовало выбора «правильной» версии — обе
  версии сохранены раздельно, ни одна не изменена.
- Историческая справка: docstring монолитного класса фиксирует, что до
  мая 2026 он выглядел как чекбокс (галочка на зелёной заливке) и был
  переделан в кольцо+точку после отзыва пользователя — расхождение с
  CheckmarkRadioButton осознанное.

ИТОГ ГЕЙТА: идентичность-по-цвету подтверждена для Pink/Blue/Orange
(12 пиксельных сценариев + посимвольный diff stylesheet); для радио-пары
