Что именно изменилось по пунктам промпта:

1. **Авто-запрос удалён.** `_do_fetch` больше не запускает ни одного воркера: выделение сегмента
   (клик по «#» или любое другое) перезаполняет панель ЛОКАЛЬНО. Debounce 300 мс и самообновление
   по `showEvent` сохранены; `🔄` теперь сбрасывает ряды (tooltip обновлён). Авто-ветка MT
   (:1581–1587 до) и её обработчики `_on_mt_result`/`_on_mt_complete` удалены. LLM в панели и раньше
   не были авто — не стали и теперь.
2. **Fetch-ряды MT.** Каждый включённый профиль («Show this profile in QuickTrans»: мастер
   `mtql_custom_mt` + `enabled` профиля + непустой endpoint — перечисление прежнее,
   `_get_enabled_providers(include_mt=True)`) получает ряд «чип профиля + подсказка
   "MT – click to fetch" + кнопка Fetch», визуально и по поведению идентичный LLM-рядам
   (`_add_llm_button` обобщён в `_add_fetch_row(..., block)`; подсказка AI-рядов прежняя
   «AI – click to fetch»). Профили без endpoint / выключенные не показываются (как раньше);
   при полном отсутствии провайдеров — прежняя заглушка «⚠️ No QuickTrans providers enabled. Click ⚙ to configure.».
3. **«Fetch all»** в заголовке каждого блока (⚡ Machine translation и 🤖 AI / LLM):
   `_make_section_header_with_fetch` + `_fetch_all_mt`/`_fetch_all_ai`. Клик запускает Fetch всех
   ЕЩЁ не заполненных рядов блока (кнопка в полёте заблокирована — повторный клик её пропускает;
   заполненные ряды уже заменены результатом и в списке отсутствуют).
4. **Результат привязан к сегменту.** Воркеры Fetch-рядов идут через `_start_worker` с текущим
   `_fetch_token` (смена сегмента → `_do_fetch` поднимает токен + `_clear_results`): поздний ответ
   отбрасывается, ряды сбрасываются в «press Fetch». Отмены запроса нет (как в Q.6 — доживает до
   ответа сервера/таймаута, QThread паркуется в `_DETACHED_WORKERS`). **Бонус-фикс:** старый путь
   `_add_llm_button` токена НЕ проверял — поздний LLM-ответ приписывался к строкам СЛЕДУЮЩЕГО
   сегмента (вставлялся в конец списка); теперь это невозможно.
5. **Link-only (Q.2).** Для link-only сегмента каждый включённый профиль (MT и LLM) сразу получает
   ряд с исходником дословно + пометкой «⤳ link-only — не отправлено»; без сети, без Fetch-кнопок,
   без «Fetch all».
6. **Нумерация.** `_renumber_rows` пересчитывает номера (1..N) и `self.suggestions` по визуальному
   порядку после каждой вставки — при ручных Fetch результаты приходят в произвольном порядке, а
   Ctrl+N должен вставлять именно тот ряд, чей номер видит пользователь.

Проба Q.3 (`batch-qb_q3_probe.py`, два фейковых loopback-endpoint'а с разными ответами, сетевая
ловушка, изолированный стаб-профиль): **17/17 post PASS** (pre на worktree `2ce27897`: 5 FAIL =
старое поведение задокументировано — 3 выделения дают 6 авто-запросов, MT-ряды без Fetch).
Ключевые: выделение 3 сегментов подряд → 0 запросов; исходные ряды ровно `[MT prof A, MT prof B,
LLM prof]` (профиль без endpoint и выключенный скрыты); Fetch одного MT-ряда → ровно 1 запрос,
именно на endpoint этого профиля (сервер B не получал ничего); «Fetch all» MT → 1 новый запрос
(только незаполненные); «Fetch all» AI → срабатывает LLM-ряд; смена сегмента в полёте (задержка
1.5 с) → поздний ответ не показан, ряды сброшены; link-only → 3 ряда с исходником и пометкой,
0 запросов, кнопок Fetch all нет. Кросс-чек: проба Q.3 на коде Q.4 — 17/17 PASS
(`batch-qb_q3_result_post_afterq4.json`).

## 2. Q.4 — редактируемое поле результата и кнопка Paste (панель)

Новый виджет **`PanelResultRow(QFrame)`** (quicktrans.py, финал :364–443) заменяет `MTSuggestionItem`
в панели (`_append_result`); попап продолжает использовать `MTSuggestionItem` — его
клик/цифры/Enter-вставки не тронуты.

1. **Поле.** `QTextEdit` с `setAcceptRichText(False)`, `setTabChangesFocus(True)`, высота следует
   тексту (`documentSizeChanged → _adjust_height`; QTextEdit выбран вместо QPlainTextEdit, т.к.
   его layout отдаёт высоту в пикселях и отслеживает перенос/ширину). Текст выделяется мышью и
   копируется, содержимое правится. Найденный пробой продукт-баг: конструктор `QTextEdit(text)`
   схлопывает `\n` в пробел — поле заполняется через `setPlainText` (переносы сохранены, что
   подтверждено пробой: поле показывает две строки). Красный текст/рамка для строк-ошибок.
2. **Paste.** Кнопка в ряду (кроме строк-ошибок): вставляет в target ВЫДЕЛЕННЫЙ фрагмент поля
   (если выделение есть), иначе весь текущий текст поля (с правками пользователя). Выдача идёт
   сигналом `paste_requested(str)` → соединён напрямую с существующим `translation_selected`
   панели → хостовое `_insert_quicktrans_translation` (Supervertaler.py:35873): в запись в target
   не добавлено ничего. `QTextCursor.selectedText()` возвращает U+2029 вместо `\n` — восстанавливается.
3. **Клик по ряду больше не вставляет.** У ряда нет `mousePressEvent`-переопределения, курсора-руки
   и hover-выделения; клик (по полю) просто ставит курсор. Панельный `_on_item_clicked` удалён.
   `MTSuggestionItem.mousePressEvent` (:229+:573–576 в финале) сохранён — это путь попапа.
4. **Ctrl+1..9 (панель) сохранены** и вставляют ТЕКУЩИЙ текст поля соответствующего ряда (не исходный
   ответ): `insert_match_by_number` работает по `self._rows` (визуальный порядок) и `current_text()`.
   Фокус в поле сочетания не перехватывает: у QTextEdit нет биндинга на Ctrl+1..9, оконный QShortcut
   срабатывает — проверено пробой настоящим `QShortcut(Ctrl+1)` + `QTest.keyClick` в сфокусированное
   поле (вставка прошла, в поле цифра не попала).
5. **Строки-ошибки.** Кнопки Paste нет; Ctrl+N их пропускает; текст ошибки в target попасть не может.
   Новый модульный помощник `_is_panel_error_text` (:83–91): ЛЮБОЙ bracket-нотис
   («[Error: …]», «[MT proxy not running. Start it.]», «[Custom MT: …]», «[No translation returned]», …)
   считается строкой-ошибки ПАНЕЛИ — флаг воркера `is_error` покрывает только тексты со словом
   «error», а пункты промпта требуют paste-недоступности и для «[MT proxy …]»/«[Custom MT …]».
   Нормализация — только в `_append_result` панели; обработка попапа не изменилась.
6. **Link-only ряд.** Paste/Ctrl+N вставляют исходник дословно (draft, как в M1), пометка не вставляется.
7. **Попап не изменён** — его пробы Q-A проходят без изменений (см. §4).

Проба Q.4 (`batch-qb_q4_probe.py`, фейковый endpoint + мёртвый `127.0.0.1:1` для ошибок; вставка
проверяется на границе сигнала `translation_selected`): **24/24 post PASS** (pre на worktree
`816dc44d`: все 3 фазы падают на `panel._rows` — фич нет). Проверено: поле редактируется и
копируется в буфер (выделение «Edite»); авто-высота one<two<four (26/44/98 px); Paste вставляет
выделенный фрагмент и весь ОТРЕДАКТИРОВАННЫЙ текст; Ctrl+N вставляет отредактированный текст;
настоящий Ctrl+1 через фокус поля; клики по бейджу и полю ничего не вставляют и фокусируют поле;
строка-ошибка («[MT proxy not running. Start it.]» с мёртвого endpoint) помечена, без Paste,
Ctrl+N отказывает, здоровый ряд того же блока вставляет; link-only ряды (2: MT + LLM) без сети,
Paste/Ctrl+N вставляют исходник дословно.

## 5. Q.7-анализ: NBSP-экспозиция пути вставки панели (БЕЗ изменения кода продукта)

### 5.1 Что делает `on_target_text_changed` при вставке

Обработчик — замыкание `make_target_changed_handler(segment_id, editor_widget)`,
def Supervertaler.py:33139, тело :33145–33317. По шагам (номера строк — текущие):

1. Собирает `new_text` из виджета: WYSIWYG-режим — `_wysiwyg_document_to_tagged_text` (пересборка
   тегов из форматирования), иначе `toPlainText()` (:33145–33155).
2. Разворачивает compact-теги (`expand_compact_tags`, :33158–33160) и невидимые маркеры
   (`reverse_invisible_replacements`, :33163) — NBSP-нормализация Qt здесь НЕ реверсится.
3. Восстанавливает скрытый внешний оборачивающий тег (`_stripped_outer_tag`, :33166–33170).
4. `_initial_load_complete = True` (:33187); окно-флаг `_suppress_target_change_handlers` —
   ранний return (:33189–33193) — механизм подавления УЖЕ существует (используется при загрузке сетки).
5. Ищет сегмент по ID (:33199–33201); запоминает old_target/old_status (:33204–33205).
6. **Идемпотентный guard**: `new_text == old_target → return` (:33221–33230) — программные вставки
   «того же» текста глотаются, но NBSP-нормализованный текст ≠ raw-тексту с NBSP, поэтому guard
   вставку НЕ глотает — модель перезаписывается нормализованным текстом.
7. `editor_widget._user_has_edited = True` (:33233) — ячейка получает личную undo-историю.
8. `target_segment.target = new_text` (:33241) — единственная запись модели.
9. Живой Document Preview: `_schedule_preview_refresh()` (:33248).
10. Ре-синх невидимых маркеров дисплея: blockSignals-wrapped `setPlainText(display_text)` +
    маппинг курсора (:33255–33288).
11. Статус: `confirmed → draft` при изменении текста + отложенный `_refresh_segment_status_by_id`
    (:33291–33299).
12. `record_undo_state(segment_id, old_target, new_text, old_status, new_status)` (:33303);
    `project_modified = True` (:33306).
13. Debounce 1000 мс → `_handle_target_text_debounced_by_id` (:33309–33317; def :37210–37253):
    `update_window_title`, `_auto_resize_single_row`, **запись в TM только при status=='confirmed'**,
    `update_progress_stats`, `_trigger_idle_prefetch`.

Итого обработчик пишет: `segment.target`, статус (confirmed→draft), undo-запись, флаг
`_user_has_edited`, `project_modified`, обновление превью/строки/тайтла/прогресса, отложенную
запись TM (только confirmed) и idle-prefetch.

### 5.3 Находка: явная запись модели в обоих QuickTrans-путях — МЁРТВЫЙ код

`_insert_quicktrans_translation` (:35891–35896) и closure попапа (:7527–7533) содержат явную
запись `self.segments[row].target = new_target` под guard'ом `hasattr(self, 'segments')`.
Проверено AST-поиском: атрибут `self.segments` на `SupervertalerQt` НИКОГДА не присваивается
(единственная запись `self.segments = segments` — :5298 внутри воркера `PreTranslationWorker`;
найденные :28742/:28757 — это `self.current_project.segments`). Следовательно: (а) явная запись
модели в этих путях не выполняется никогда — модель пишет ТОЛЬКО textChanged-обработчик;
(б) вызываемый там `self.mark_segment_modified(...)` (:7533, :35896) — метод, которого НЕ СУЩЕСТВУЕТ
ни в монолите, ни в модулях (grep по всему репо — 2 вызова, 0 определений); дойдя до выполнения, он
бросил бы AttributeError, но guard (а) гарантирует, что не дойдёт. Для Q-C это значит: «просто
обернуть setPlainText в blockSignals» в путях QuickTrans **оставит модель вообще без обновления**
(подсказка промпта подтверждается кодом) — сначала нужно восстановить живую явную запись
(`current_project.segments[row].target = <сырой текст>`).

### 5.4 Варианты минимального безопасного фикса (для Q-C; решает координатор)

**Вариант A — «сырой текст в модель до setPlainText + NBSP-нечувствительный guard».**
На каждом сайте: сегменту пишется СЫРОЙ текст ДО setPlainText (10 из 14 уже так делают — №3,5–14);
обработчик расширяется: ранний return также при NBSP-нормализованном равенстве
(`new_text.replace('\xa0',' ') == old_target.replace('\xa0',' ')`).
+ Модель сохраняет NBSP везде; один общий guard вместо 14 обёрток; обработчик остаётся живым для
  ручных правок; сайт №14 (sync по обработчику) продолжает работать (его модель уже равна — guard
  вернётся рано, модель сырая — корректно); Qt-очередные события после setPlainText гасятся тем же
  guard'ом.
− Трогается ОБЩИЙ обработчик всех правок (риск выше, нужен точный компаратор); ручная правка «только
  NBSP↔пробел» будет считаться идемпотентной (экзотика); программные вставки перестают получать
  побочные эффекты обработчика (undo «как ручной правки», сброс confirmed→draft, `_user_has_edited`,
  превью) — у сайтов, которые не делают это сами (например №1/2/4 — после починки мёртвого кода,
  №9), поведение изменится заметно: статус confirmed останется confirmed после вставки → дебаунс-ТМ
  сохранит НОВЫЙ текст в TM как подтверждённый. Значит вариант A требует явной установки статуса
  draft на QuickTrans-путях (или в самом обработчике до раннего return).

**Вариант B — «blockSignals (или существующий `_suppress_target_change_handlers`) вокруг setPlainText
+ явная запись модели на сайте».** Узор M2.3, применённый на каждый сайт.
+ Локальность: общий обработчик не трогается; модель и так сырая у сайтов №3,5–14; подавление
  очередных Qt-событий уже обеспечивает идемпотентный guard.
− 14 пер-сайтных правок с пер-сайтной проверкой недостающих эффектов: у кого нет своей undo-записи
  (№5 частично, №9 — undo только статусный, №10 свой есть…), у кого нет сброса статуса; потеря
  живого обновления превью на программных вставках; **фатально для №1/2/4 без предварительной
  починки мёртвой записи (§5.3) и недопустимо для №14** (прямой комментарий требует сигналы не
  блокировать) — эти сайты нуждаются в A-компоненте или индивидуальном перепроектировании.

**Рекомендация для Q-C:** гибрид — (1) починить мёртвую явную запись модели в QuickTrans-путях
(№1/2/4, включая удаление фантомного `mark_segment_modified`) с явной записью сырого текста и
статуса draft; (2) вариант B для сайтов №3,5–13 (уже пишут модель сами; добить недостающие
undo/статус по месту); (3) №14 оставить на обработчике (либо A-guard). Обязательна проба типа
M2.3-S0/S1 на каждый сайт (NBSP-исходник → вставка → модель содержит `\xa0`) и повторный прогон
16-этапного набора. Оценка: ~14 правок сайтов + 1 guard + 1 починка мёртвого кода; риск средний
(общий обработчик и TM-семантика статусов).
