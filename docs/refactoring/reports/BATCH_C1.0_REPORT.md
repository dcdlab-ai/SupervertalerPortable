## 0. Ключевая улика о самих образцах

Три входных файла — это **Tagged Text-документы** (фикстуры I-серии). Только
`T-I2b_Input.tagged.txt` **содержит цитируемые фрагменты как собственное содержимое**
(строки 96–118 по порядку документа):

* `:96` `<ParaStyle:p><CharStyle:…>ОКРУЖАЮЩИЕ СЕГМЕНТЫ ДЛЯ КОНТЕКСТА:<CharStyle:>`
* `:97` `(Сегмент, отмеченный \>\>\> \<\<\<, подлежит переводу)`
* `:98–:119` нумерованные строки `25. …`, `26. …`, `27.`, `28.`, `29.`
* `:118` `\>\>\> 30. ### ЦЕЛИ И ПОБЕДА  \<\<\<  [ПЕРЕВЕСТИ ЭТО]`
* `:119` `31.`, `33.`

`docling_Input.tagged.txt` и `pymupdf4llm_Input.tagged.txt` таких строк **не содержат**
(0 совпадений). То есть T-I2b — документ, в который **вморожен загрязнённый вывод модели**:
эхо-блок попал в target, прошёл экспорт и стал абзацами документа. Вывод для защиты (§5):
случай «исходный сегмент сам содержит `>>> … <<<`» — не гипотетический, он уже есть в реальном
файле, и детектор обязан его не флагать.

Соответствие цитат Дмитрия маркерам промта (все — русский перевод английских литералов промта,
сделанный самой моделью):

| Цитата из эха | Литерал промта | Где |
|---|---|---|
| «ОКРУЖАЮЩИЕ СЕГМЕНТЫ ДЛЯ КОНТЕКСТА:» | `**SURROUNDING SEGMENTS FOR CONTEXT:**` | Supervertaler.py:48525 |
| «(Сегмент, отмеченный >>> <<<, подлежит переводу)» | `(The segment marked with >>> <<< is the one to translate)` | Supervertaler.py:48526 |
| «>>> 30. ### ЦЕЛИ И ПОБЕДА <<< [ПЕРЕВЕСТИ ЭТО]» | `f">>> {seg.id}. {seg.source} <<<  [TRANSLATE THIS]"` | Supervertaler.py:48519 |
| «13. ## ОСОБЫЕ ПРАВИЛА», «27.», «28.» | `f"{seg.id}. {seg.source}"` (нумерованные соседи, source — md-заголовок или пустая строка) | Supervertaler.py:48523 |

Модель (nailong-9b) перевела **и служебные литералы, и исходники соседей** («SPECIAL RULES» →
«ОСОБЫЕ ПРАВИЛА»). muse-glimmer-30b и qwen3.8-27b эхо не воспроизводят.

## 1. Где собирается промт одиночного сегмента с контекстом

**Единственное место** — `SupervertalerQt.translate_current_segment` (def на `Supervertaler.py:48332`),
блок контекста `:48504–48531`:

* `:48504` — `surrounding_segments = general_prefs.get('surrounding_segments', 5)` — настройка
  профиля (UI-спин `:19530/:19546`, сохранение `:22917/:23070`, дефолт 5);
* `:48510–48514` — окно соседей `start_idx..end_idx` вокруг текущей строки;
* `:48519` — маркированный сосед: `f">>> {seg.id}. {seg.source} <<<  [TRANSLATE THIS]"`;
* `:48523–48524` — соседи: `f"{seg.id}. {seg.source}"` и, если есть target, `f"    → {seg.target}"`;
* `:48525–48526` — заголовок и пояснение (литералы);
* `:48546–48556` — блок вставляется в `custom_prompt` **перед** delimiter:
  `custom_prompt.replace("**YOUR TRANSLATION", surrounding_context + "\n\n**YOUR TRANSLATION")`,
  fallback — конкатенация в хвост.

Delimiters **не** в этом блоке — их строит менеджер промтов:
`modules/unified_prompt_manager_qt.py:4159` —
`final_prompt += "\n\n**YOUR TRANSLATION (provide ONLY the translated text, no numbering or labels):**\n"`.

**Хранение:** все маркеры — **литералы** внутри f-строк/строковых литералов, констант нет нигде.
Язык — один, английский. Нумерация — реальные `seg.id` проекта (поэтому в эхе «27.», «28.»,
«>>> 30. …»). Блок контекста добавляется только при `surrounding_segments > 0` и
`len(surrounding) > 1`.

## 2. Где разбирается ответ и записывается в target

Все вызовы проходят через один конвейер `modules/llm_clients.py`:

1. `translate()` `:621` → делегирует `translate_with_usage()` `:667` (Batch #9.3: единственный
   провайдер `custom_openai`, иначе ValueError);
2. `_call_openai_with_usage()` `:733` → сетевой вызов;
3. `_parse_completion_response()` `:273` — **уже есть очистки:** чтение `finish_reason`;
   `reasoning_content` никогда не используется как перевод; inline `<think>/<thinking>`-блоки
   вырезаются (regex `:120–127`); dangling-закрывающий тег → берётся текст после последнего
   `</think>`; незакрытый `<think>` → `LLMTruncatedError`; пустой ответ → `LLMEmptyResponseError`;
   `finish_reason='length'` в строгом (переводном) пути → `LLMTruncatedError` с `partial_text`;
4. `_clean_translation_response()` `:428` — **очистки от эха промта уже есть, но не те:**
   * сплит по delimiter-маркерам — локальный список из 10 строк `:436–447`
     («**YOUR TRANSLATION (provide ONLY…» , «**YOUR TRANSLATION**», «Translation:», голландские
     «JOUW VERTALING» и т.п.); берётся текст **после** маркера, с порогом «стало короче на ≥10%»;
   * счётчик «prompt patterns» (английские + голландские фразы «As a professional», «Uw taak is
     om»…): если ответ >300 символов и ≥3 паттерна — построчная чистка (порог <70% длины);
   * финальный `_remove_prompt_patterns()` `:578` — выкидывает строки с паттернами и очень
     длинные строки-инструкции.

**Чего нет:** маркеров блока контекста («SURROUNDING SEGMENTS», «>>>», «TRANSLATE THIS») нет ни
в одном списке; русских паттернов нет вовсе; markdown-ограждения ``` не срезаются.
Принципиальное ограничение: nailong-9b **переводит** эхо — англоязычные списки по определению
не ловят «ОКРУЖАЮЩИЕ СЕГМЕНТЫ ДЛЯ КОНТЕКСТА».

**Запись в target** — в самом монолите, без доп. проверок: `:48636` `segment.target = translation`,
`:48639–48645` — грид, `:48649+` — `tm_database.add_to_project_tm(...)` → эхо попадает **и в TM**.
Статус — «draft», undo-запись пишется.

## 5. Минимальный дизайн защиты

### 5.1 Определение эха

Главный факт: nailong-9b **переводит** служебные литералы, поэтому текстовое совпадение с
английскими константами ненадёжно. Надёжные **структурные** сигналы, переживающие перевод:

1. **парные `>>>` и `<<<` в ответе, которых нет в исходном сегменте** — главный сигнал
   (в образце сохранены: `>>> 30. ### ЦЕЛИ И ПОБЕДА <<<`);
2. `>>>\s*\d+\s*\.` — нумерованный маркированный сегмент (форма `:48519`);
3. дешёвый текстовый бонус: литерал `SURROUNDING SEGMENTS FOR CONTEXT` (ловит модели,
   которые не перевели каркас; переведённое эхо ловится пп. 1–2).

**Условие срабатывания:** маркер есть в ответе **И отсутствует в исходном сегменте**.
Это критично: фикстура T-I2b сама содержит «>>> 30. … <<< [ПЕРЕВЕСТИ ЭТО]» как контент —
такой сегмент легитимно переводится с теми же маркерами и НЕ должен флагаться.

Чего детектор **не** делает: не ловит голые «27.», «28.» без `>>>` (слишком слабый сигнал,
markdown-нумерованные списки легитимны) и не пытается вырезать перевод из мусора — по условию
координатора.

### 5.2 Где и что делать при срабатывании

* Функция `looks_like_prompt_echo(response, source_text) -> bool` + константы маркеров —
  в клиентском слое (`modules/llm_clients.py` или новый `modules/prompt_markers.py`), вызов
  из `translate_with_usage` после `_clean_translation_response`. Возврат: `None` (перевод
  отсутствует) — тогда путь 1 падает в существующую ветку «Translation failed» с **точной**
  причиной в логе, или typed-ошибка `LLMPromptEchoError` (симметрично G3.2) — решает координатор.
* Поведение: **не записывать в target, не пополнять TM, не писать undo**; сегмент остаётся в
  прежнем статусе. Один **повтор запроса** (прецедент: AutoTagger `max_attempts`,
  modules/tag_manager.py:1430) — если чистый ответ не пришёл и со второго раза, пропуск
  с предупреждением.
* Сообщение пользователю: строка в лог `⚠ Эхо промта (окружающий контекст) в ответе модели —
  сегмент #N оставлен без перевода (модель: <provider/model>)` + статус-бар. Ничего модального.

## 6. Оценка объёма и список тестов

### Объём

* Константы + `looks_like_prompt_echo` + интеграция в `translate_with_usage`: ~50–70 строк
  (модуль) + ~10–15 строк интеграции + ~5 строк в `translate_current_segment` для внятного
  лога/повтора.
* Повтор запроса (если Q2=«1 повтор»): +~15–20 строк.
* Tagged Text warning: ~20–30 строк в writer + 2–3 теста.
* Итого: масштаб одной короткой сессии (уровень I2.1). Продукт: `modules/llm_clients.py`
  (+ новый модуль констант) и/или `Supervertaler.py` (точечная вставка), `modules/tagged_text/writer.py`.

### Тесты (фикстуры — строки из образцов T-I2b)

1. **Эхо, переведённое на русский** (целиком: «ОКРУЖАЮЩИЕ СЕГМЕНТЫ ДЛЯ КОНТЕКСТА:» + «(Сегмент,
   отмеченный >>> <<<…)» + «>>> 30. ### ЦЕЛИ И ПОБЕДА <<< [ПЕРЕВЕСТИ ЭТО]» + «27.»/«28.») при
   source без `>>>` → детект, target не записан.
2. **Эхо на английском** (оригинальный литеральный каркас) → детект.
3. **Ложное срабатывание №1:** source сам содержит «>>> 30. … <<< [ПЕРЕВЕСТИ ЭТО]» (строка 118
   фикстуры T-I2b) → НЕ детект (маркер есть в source).
4. **Ложное срабатывание №2:** source — markdown-нумерованный список «1. … 2. …», ответ —
   его перевод → НЕ детект.
5. **Голые номера:** ответ = «27.» при коротком source → НЕ детект (осознанное ограничение,
   зафиксировать в тесте как контракт).
6. Нормальный перевод с кавычками/цифрами/эмодзи → НЕ детект.
7. **Интеграция:** `translate_current_segment` с клиентом-заглушкой, вернувшей эхо → target
   не изменился, TM не пополнился, в логе предупреждение, статус сегмента прежний.
8. **Повтор:** первый ответ — эхо, второй — чистый перевод → target записан; оба ответа — эхо →
   пропуск с предупреждением.
9. **Tagged Text:** экспорт проекта, где target содержит эхо → предупреждение с номерами строк.
10. **Tagged Text:** target легитимно повторяет «>>>» из source → без предупреждения.
