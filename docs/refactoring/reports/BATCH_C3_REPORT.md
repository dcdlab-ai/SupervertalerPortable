## §1. Правила срезания, пороги, таблица пар, FP-анализ

`strip_prompt_leaks(response, source_text, segment_number) -> (text, removed: list[str])`
в `modules/prompt_markers.py` (+140 строк, модуль уже tracked — **нового tracked-модуля нет**,
importsmoke/zip не расширяются). Чистая функция, без Qt и побочных эффектов. Правила
применяются итеративно в порядке **(в) → (б) → (а)**, результат `strip()`; каждый срабатывает
ТОЛЬКО по сочетанию структурных признаков. Пустой после срезания ответ вызывающий код трактует
как эхо (сценарий C1: один повтор без контекста → пропуск).

**(в) хвостовая строка-инструкция** — последняя непустая строка ответа, ЦЕЛИКОМ совпадающая с
каркасом (анкор `^…$`, не подстрочный хвост): `необязательные **` + заголовок без `*`/переносов
**до 40 знаков** + `(`скобки с текстом **10–200 знаков**`)` + необязательное двоеточие +
`необязательные **`. Дополнительные условия: строки нет в source **дословно**; в строке есть
признак-разделитель — **двоеточие ИЛИ `**`** (FP-заслон, см. ниже). Срезается строка целиком.

**(б) хвостовая метка в квадратных скобках** — ответ оканчивается `[...]`, внутри скобок
**1–3 слова, ≤30 знаков, только буквы верхнего регистра, пробелы и дефисы** (мин. слово —
3 буквы). Срезается метка вместе с пробелами перед ней. Не метка: цифры, строчные буквы,
точки (`[sic]`, `[2024]`, `[см. приложение]`), слова <3 букв (`[OK]`, `[ОК]`), вложенные
скобки (содержимое не может содержать `[`/`]` — regex не матчится вовсе). Правило выключено,
если source оканчивается на `]`.

**(а) префикс номера** — ответ начинается с «N.» (N — число), N == `segment_number`, и source
сам не начинается с числа (`^\s*\d+\s*[.)]` — выключает правило при ЛЮБОМ ведущем номере
source: и совпадающем «8.», и другом «3.», F4а/F4б). Защита от десятичных дробей `(?!\d)`:
«8.5 см» для сегмента №8 не срезается. Срезается «N.» + один пробел.

**FP-анализ (сознательные остатки риска):**
1. Легитимная финальная строка вида «Итого (все три категории):» (заголовок ≤40, скобки ≥10,
   двоеточие) будет срезана — это остаточный FP правила (в), осознанный компромисс координатора
   (форма правила задана промптом). Смягчение: срезанный фрагмент попадает в `removed` и в
   английский лог «removed prompt artefact(s) …»; target пишется в undo — восстановимо.
2. Голая строка «Заголовок (пояснение)» **без двоеточия и без `**`** — НЕ срезается
   (FP-заслон добавлен: P21/P39 в таблице; без него срезался бы целиком легитимный однострочный
   перевод вида «Название главы (см. примечания ниже)» → сегмент ушёл бы в «эхо»-пропуск).
3. Ответ-целиком-каркас → пусто → сценарий C1 (повтор без контекста, затем пропуск).
   Легитимный однострочный перевод, точно совпавший с формой каркаса (заголовок ≤40 + скобки
   ≥10 + двоеточие), ушёл бы в пропуск — редкая форма, покрыта логом.
4. «[ПЕРЕВЕСТИ 2]»/«[см. приложение]» — меткой не считаются (цифры/точки), при этом
   префикс номера всё равно срезается (P16/P17).
5. Ложный префикс: перевод, легитимно начинающийся с «N.», при source без ведущего числа
   (например source «First item» → ответ «1. Первый пункт» при N==id) — срезается. Принято:
   в блоке контекста модель нумерует сегменты тем же номером, и такой ответ почти всегда
   эхо-нумерация; источник риска — нумерованные списки в source, но тогда source начинается
   с числа и правило выключено (P06/P19).

**Таблица пар** — 39 строк (F1–F4 + границы, русские/английские/пустые/None), живёт в
`docs/refactoring/audits/c3_prompt_leaks_tests.py` ч. A: **A-часть 42/0** (39 пар + счётчик
≥25 + проверка removed F1/F3). Эталоны: P01=F1, P03/P04=F2, P05=F3, P06/P07/P08=F4; ключевые
границы: P11 («8.» без пробела), P12 (десятичная дробь), P16/P17 (цифры/точки в скобках),
P18 (source с «]»), P21 (скобка внутри текста), P27 (вложенные скобки), P29 (скобки <10),
P30 (заголовок >40), P36 (номер ≠ id), P38/P39 (болд без двоеточия / голая строка),
P22–P26 (комбинации двух-трёх правил), P23/P24 (ответ целиком метка/номер → пусто).

## §2. Чем нумеруется блок контекста (ответ на вопрос координатора)

Блок окружающих сегментов в `translate_current_segment` нумеруется **id сегмента** (`seg.id`),
НЕ индексом строки грида: `f">>> {seg.id}. {seg.source} <<<  [TRANSLATE THIS]"` (:48687) и
`f"{seg.id}. {seg.source}"` (:48689) — строка «8. АНГЛИЧАНЕ» в ответе модели эхо-нумерует
сегмент с id=8. В правиле (а) `segment_number` — именно `segment.id` во всех трёх точках
вызова (§5). Расхождение row≠id возможно после удалений сегментов — сравнение с индексом
грида дало бы ложные несрабатывания/срабатывания, поэтому якорь — seg.id. В сьюте
(p. B2/B8/B9) ответы-фикстуры строятся от реального `seg.id` (прогон поймал бы ошибку
сравнения с индексом: жёсткое «8.» в фикстуре не срезалось бы у сегмента с id=2).

## §3. Интеграция в translate_current_segment и предпроход экспорта

**Интеграция (коммит 2, монолит):** срезание на КАЖДОМ ответе клиента, ПОСЛЕ очистки
`_clean_translation_response` (внутри клиента) и ДО детекторов C1/C2:
- первый ответ (:48855–48915): срезание → при removed английский лог
  «Segment #N: removed prompt artefact(s) from response: <кратко>» (фрагменты через `; `,
  обрезка 150 знаков) → если ответ целиком каркас (пусто после срезания) — сценарий C1:
  при `_overflow_request_had_context` один повтор без блока контекста (промт чистится тем же
  способом, что в C1/C2-повторах), ответ повтора тоже срезается; каркас в повторе или эхо —
  `echo_skipped`; запрос уже был без контекста → сразу пропуск;
- ответ эхо-повтора C1 (:48942–48952): срезание; каркасный повтор → отказ (второй попытки нет,
  как у повторного эха); строка «↻ Retry without surrounding context…» сохранена (сьют c1 33/0);
- ответ перелив-повтора C2 (:48944-блок C2): срезание ПЕРЕД повторной проверкой перелива
  (срезание может снять ложный перелив от каркасных строк); каркасный повтор → отказ.
Детекторы C1/C2 и их сообщения НЕ менялись; c1 33/0 и c2 75/0 подтверждены прогонами.

**Предпроход экспорта (коммит 3, дыра C2):** в `export_tagged_txt` (:30270–30305), сразу после
принятия диалога соответствий и ДО сборки md-строк — предпроход по СЕГМЕНТАМ:
- ячейки (table_info длины 4, формат TBL1.2; legacy docx — кортеж длины 3 — «обычный»):
  `looks_like_context_overflow` → «возможный перелив контекста (ячейка, сегмент #N): …»;
  `looks_like_prompt_echo` → «похоже на эхо промта (ячейка, сегмент #N): …» — причина:
  в строке table_row переносы внутри ячейки склеены в пробел (`escape_cell`), построчный
  детектор писателя на такой строке не видит перелив;
- ВСЕ сегменты (и ячейки, и обычные): `strip_prompt_leaks(target, source, seg.id)` → при
  removed «остатки разметки промта в переводе (сегмент #N): …» — только предупреждение,
  target НЕ меняется.
Предупреждения вставляются НАВЕРХ `report.warnings` (:30328) → в окне отчёта эхо-строки
попадают в красный блок, как у C1/C2 (фильтр `_show_tagged_text_report` по подстроке
«похоже на эхо промта»). Экспорт не блокируется. Для обычных сегментов overflow/echo
остаются за существующей проверкой писателя — дублей нет (проверено C5 сьюта: обычный
перелив даёт ровно «(строка N)» от писателя и ни одного «(ячейка…)»).

## §4. Разведка (без правок кода)

### 4а. Консоль: зависание при клике (QuickEdit)
**Как программа пишет в stdout:** `log()` первым делом делает `print(f"[LOG] {message}")`
(Supervertaler.py:47531) — из ЛЮБОГО потока (фоновые воркеры пишут print напрямую, в UI —
через сигнал). `sys.stdout` заменён на `_Tee` (:54721) — оригинальный консольный поток +
`supervertaler.log`. Дополнительно печатают: Qt-message-handler (:54789–54795), stdlib-logging
→ stdout (:54811), i18n-сообщения в main(). Т.е. в консоль пишут и GUI-поток, и воркеры.

**Механика зависания:** режим QuickEdit («Выбрать») в cmd.exe — клик по консольному окну
переводит консоль в выделение; ЛЮБОЙ WriteFile в консольный handle из любого потока

зависание воркера (и join'ов на нём).

**Место для правки (не реализовано):** `main()` (Supervertaler.py:54824), сразу после
`_setup_diagnostic_log()` (:54832) и до QApplication — снять `ENABLE_QUICK_EDIT_MODE (0x0040)`
с реального консольного handle:

```python

    try:
        import ctypes
        kernel32 = ctypes.windll.kernel32
        _h = kernel32.GetStdHandle(-10)          # STD_OUTPUT_HANDLE
        _mode = ctypes.c_uint32()
```

замораживает вывод; «Mark»-режим из системного меню сохраняется); на данные, файлы и реестр
не влияет. Прецедент-паттерн (try/except + guard) уже есть рядом — `SetErrorMode` :55007–55017.
Альтернатива (больше изменений): не подключать консоль вовсе (pythonw в start.bat).

### 4б. «Падение без сообщения» (T-C5 PyMuPDF): анализ + моделирование
**Структура защиты в translate_current_segment:** всё тело перевода (:48529–:48926) обёрнуто
`try/except Exception` → «✗ Translation error» в лог + модальное critical. Исключение в слоте
ДО try (:48464–48528: предупреждения, `self.current_project.segments[current_row]`,
проверки настроек) — единственная Python-поверхность вне except (кандидат: IndexError при
рассинхроне строки грида со списком сегментов).

**Факт о PyQt6 (проверено отдельным офскрин-пробником, stage
`batch-c3/checks/check_qt_slot_exception.py`):** при необработанном исключении в слоте
PyQt6 вызывает `sys.excepthook`; если хук ДЕФОЛТНЫЙ — следом qFatal() → abort (тихое падение
без сообщений, процесс умирает); если хук ЗАМЕНЁН — хук вызывается и процесс ПРОДОЛЖАЕТ
работу. Приложение ставит свой хук `global_exception_handler` (:54839–54849, печать полного
трейсбека в stdout/tee → supervertaler.log) → в ЭТОМ приложении исключение в слоте НЕ убивает
процесс: трейсбек уходит в консоль/журнал, программа продолжает работу.

**Вывод:** ни одна Python-ветка C1/C2-кода не может дать «тихое падение без сообщения»:
- переменные, определённые только в одной ветке, не читаются вне своих веток:
  `surrounding_context` инициализирован ДО try (:48617, коммент C1), `custom_prompt`/`images`
  — до веток, `echo_skipped`/`overflow_skipped`/`_overflow_request_had_context` — :48752–48758,
  `_retry_prompt` живёт и умирает внутри своей ветки;
- falsy-ответы (None/пустая строка) корректно пропускают проверки C1/C2 (`if translation and
  …`) и уходят в ветку «Translation failed»;
- доступ к атрибутам None-значений в C1/C2-блоке не найден.

**Моделирование (офскрин, заглушка LLM — 6 сценариев координатора, stage

### 4в. Как уменьшить частоту эха на коротких source (не реализовано)
**Факты:** эхо почти всегда на заголовках и коротких ячейках до ~40 знаков; ~каждый 5-й
запрос к nailong-9b. Триггер — сам вид блока: короткий source окружается нумерованным
списком из до 11 сегментов (с source+target соседей) и маркером «>>> N.» — модель
принимает блок за контент.

**Кандидаты (оценка):**
1. **Уменьшить окно для коротких source** (рекомендуемый): при
   `len(segment.source) <= N` (N≈60 знаков — граница C2 `_OVERFLOW_SHORT_SOURCE_CHARS`)
   ограничить `surrounding_segments` до 1 соседа (или 0). Точечный эффект именно там, где
   эхо; длинные сегменты сохраняют полный контекст. Влияние на e2e-агрегат: Ctrl+T-запрос
   e2e содержит блок контекста → **байты промта меняются → e2e-агрегат 982e72a247f0a6ac
   изменится**; сьюты c1/c2 содержат байт-точные проверки сборки промта (SURROUNDING-блок)
   → потребуют согласованную правку эталонов. Отдельный микробатч с обновлением эталонов,
   не «заодно».
2. Не посылать контекст вовсе для коротких source (N=∞): сильнее бьёт по частоте эха,
   но теряет жанровый якорь; тот же ценз на e2e/c1/c2.
3. Оставить контекст, убрать «нумерованный список» (разворачивать в прозу) — глобально
   меняет шаблон промта для ВСЕХ сегментов; самый широкий ценз на эталоны; не рекомендую.

**Оценка влияния на качество:** короткие заголовки/ячейки редко нуждаются в соседях для
терминологии (термбаза и глоссарий внедряются независимо от блока контекста); потеря
минимальна. Выигрыш: на каждую устранённую эхо-попытку — минус один повторный запрос
(латентность ×2 + токены). Частота: эхо-случаи, недолотленные C1 (переведённые метки,
F1–F3), теперь частично гасятся срезанием C3 — комбинация «короткий source → узкий контекст»
+ C3-срезание закрывает оба механизма утечки. Рекомендация: вариант 1, N≈60, window=1,
английский лог «short source — reduced context window»; отдельно, с согласованным обновлением
e2e/c1/c2-эталонов.
